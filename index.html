Риски и открытые вопросы

RISK

Пропуски детекции

Любой пропуск означает, что ПД ушли в регион. Нужен размеченный тестовый набор на местных данных и регулярная проверка распознавателей.

RISK

Косвенная идентификация

Без явных идентификаторов человека иногда можно узнать по контексту: должность, город, редкое событие. Маскировка по сущностям это не закрывает.

OPS

Обход шлюза

Шлюз работает, только если других путей к LLM нет: блокировка на периметре, отсутствие AWS-кредов у приложений, контроль SaaS-ИИ.

OPS

Файлы и стриминг

PDF, изображения и потоковые ответы требуют отдельной обработки: извлечение текста до маскирования, проверка ответа по мере генерации.

QUESTION

Логи в регионе

Invocation logging выключен по умолчанию. Если его включат, в регионе окажутся полные тексты запросов: решить заранее, нужен ли он.

QUESTION

Поддержка

LiteLLM и Presidio это open source. Кто сопровождает решение у заказчика: своя команда, партнёр или вендор.

QUESTION

Задержка

Детекция добавляет время к каждому запросу. Замерить на реальных промптах и длине контекста заказчика.

QUESTION

Правовая оценка

Достаточно ли выбранного режима маскирования для местного закона о персональных данных, определяет юридическая служба заказчика.

Components

Everything in the customer country runs as containers on regular VMs, Kubernetes or AWS Outposts. No GPU needed: there is no local LLM inference, only PII detection.

GATEWAY

LiteLLM proxy

Self-hosted gateway with an OpenAI-compatible API. Applications get gateway virtual keys, not AWS access.

  • Presidio guardrail modes: pre_call, during_call, post_call, logging_only, pre_mcp_call; MASK or BLOCK action per entity type
  • Separate endpoint to call a guardrail directly from other services
  • The same mechanism applies to MCP tool calls
Presidio guardrailapply_guardrailMCP guardrails
DETECTION

Presidio Analyzer

Finds entities in text using regex, NER and context words; each match gets a confidence score.

  • Built-in recognizers: names, email, phone numbers, cards and more
  • Country-specific recognizers: national IDs, document numbers, internal IDs. Need a pattern, context and a checksum where one exists
  • Confidence threshold and allow-list are configurable to avoid stripping public data
AnalyzerDeveloping recognizers
ANONYMIZATION

Presidio Anonymizer

An operator is set per entity type. By default the value is replaced with the type name, e.g. <PERSON>.

  • replace, redact, mask, hash: irreversible
  • encrypt + deanonymize: reversible, the key stays in-country
  • Community pseudonymizer for LiteLLM: swaps names for fictional ones and restores originals in the response
AnonymizerOperatorspalena-litellm-pseudonymizer
MODEL

Amazon Bedrock

LiteLLM calls Bedrock through the bedrock/ provider (Converse, Invoke and other routes). Auth via boto3: gateway IAM role or profile.

  • Applications hold no AWS credentials; only the gateway can reach models
  • Allowed models and Regions are set by gateway policy

Link to the Region

Direct Connect or Site-to-Site VPN to a VPC in the Region, then the Bedrock interface endpoint. Model traffic does not go over the internet.

  • Gateway egress allowed only to the Bedrock endpoint
  • Direct application egress to LLM providers is blocked at the perimeter
Bedrock + PrivateLinkInterface endpoints

  • Runs in the Region, so it only sees the already sanitized prompt
  • Useful as a check that local masking missed nothing, and as a response filter
  • Prompt attack filter: jailbreak, prompt injection and prompt leakage (the latter Standard tier only)

Two masking modes

The mode determines what exactly reaches the Region. Whether a mode is sufficient under local law is for the customer's legal team to assess.

MODE A · IRREVERSIBLE

Redaction / replacement

OPERATORS
replace, redact, mask
TO REGION
Customer <PERSON>, ID <NATIONAL_ID> requests...
RESPONSE
Comes back with placeholders; the app fills in data itself if needed
PROS
No link between tokens and people anywhere; simpler audit
CONS
Model quality drops when the task depends on concrete values
MODE B · REVERSIBLE

Pseudonymization

OPERATORS
encrypt + deanonymize, or stable fictional names
TO REGION
Customer Person_7f3a (or "Maria Ivanova") requests...
RESPONSE
Gateway restores originals; the user sees real names
PROS
Natural UX; the model keeps relations between entities
CONS
Pseudonymized data is generally still treated as personal data. Requires key storage

Risks and open questions

RISK

Detection misses

Any miss means PII reached the Region. Requires a labeled test set on local data and regular recognizer checks.

RISK

Indirect identification

Without explicit identifiers a person can sometimes be recognized from context: role, city, rare event. Entity masking does not cover this.

OPS

Gateway bypass

Works only if there is no other path to LLMs: perimeter blocking, no AWS credentials in apps, control of SaaS AI tools.

OPS

Files and streaming

PDFs, images and streamed responses need separate handling: text extraction before masking, response checks during generation.

QUESTION

Logs in Region

Invocation logging is off by default. If enabled, full request texts are stored in the Region: decide upfront whether it is needed.

QUESTION

Support

LiteLLM and Presidio are open source. Who operates the solution: in-house team, partner or vendor.

QUESTION

Latency

Detection adds time to every request. Measure on the customer's real prompts and context lengths.

QUESTION

Legal assessment

Whether the chosen masking mode is sufficient under local data protection law is determined by the customer's legal team.
